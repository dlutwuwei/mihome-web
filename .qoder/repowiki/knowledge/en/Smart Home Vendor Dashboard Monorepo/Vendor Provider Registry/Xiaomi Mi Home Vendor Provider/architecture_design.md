The module exposes a single `xiaomiProvider` object in `index.ts` conforming to the shared `VendorProvider` interface from `../types.js`, delegating to four internal layers:
- `auth.ts` — multi-step account flows (`loginPassword`, `beginEmail2fa`/`verifyEmail2fa`, `beginQr`/`pollQr`, `checkSession`, captcha/QR image fetch). It drives cookie-based HTTP against `account.xiaomi.com` using `http.ts`'s `CookieJar`, `follow`, and `parseJsonBody`.
- `api.ts` — signed & RC4-encrypted calls to the regional MIoT cloud (`regionHost` + `/app` base), building `_nonce`/`signedNonce`/`rc4_hash__`/`signature` fields via `crypto.ts` and decrypting responses with `decryptRc4`.
- `devices.ts` — MIoT spec-driven device model: fetches home/device lists, pulls per-device specs from `miot-spec.org`, translates them into generic `VendorField`/`VendorAction` structures consumed by `controls/index.js`'s `buildPanel`, and implements `listDevices`/`refreshLive`/`getDeviceDetail`/`setProperty`/`runAction`.
- Shared state & crypto: `state.ts` defines `XiaomiAuthState` (cookie jar, UA, region, tokens, QR/captcha URLs) plus `REGIONS` mapping; `crypto.ts` provides nonce/signature/RC4 primitives; `labels.ts` maps MIoT URN descriptions to localized labels.
Dependency direction is strictly inward: `index.ts` → auth/devices → api → crypto/state/http; nothing inside this module imports from sibling providers.
