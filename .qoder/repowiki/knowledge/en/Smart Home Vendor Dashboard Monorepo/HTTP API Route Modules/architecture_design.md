Each file is an independent Express `Router` (`authRouter`, `devicesRouter`, `keysRouter`, `profilesRouter`, `metaRouter`, `openRouter`) that mounts a flat set of routes under `/api/...`. Routes are thin controllers: they parse request bodies/params, resolve the active hub via `readHubId` cookie or an API Key bearer token, delegate business logic to `../core/*` (session, registry, apikey, status) and to provider implementations via `getVendor(session.vendorId)`. Two auth styles coexist: session-based routes in `auth.ts` / `devices.ts` / `keys.ts` / `profiles.ts` rely on a `hub` cookie, while `open.ts` implements its own middleware that verifies an API Key, enforces scopes (`devices:read`, `devices:control`, `devices:live`), throttles by IP, and records every request through `recordAudit`. Error handling is centralized — route handlers catch errors, map `AppError` instances to their `.status`, and pass all responses through `toPublicError` before JSON serialization. File uploads (print endpoint) use Busboy directly inside the handler rather than a shared middleware.
