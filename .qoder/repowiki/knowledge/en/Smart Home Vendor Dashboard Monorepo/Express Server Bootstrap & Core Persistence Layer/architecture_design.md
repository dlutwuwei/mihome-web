Two entry points compose the process: `src/index.ts` calls `bootstrapProviders()` (from `./providers`) then `createApp()` from `src/app.ts`, which mounts route modules under `/api/*` (`auth`, `devices`, `keys`, `meta`, `open`, `profiles`) and serves static assets from `../public`. The `src/core/` directory is framework-agnostic and defines a strict dependency direction: `errors.ts` is the leaf; `session.ts` and `apikey.ts` depend only on `errors.ts`; `registry.ts` depends on `errors.ts` and exposes the singleton `VendorProvider` map populated by providers at startup; `status.ts` depends on `registry.ts` + `session.ts` to probe vendor sessions. Stateful modules own their persistence: `apikey.ts` uses Node's `DatabaseSync` (SQLite WAL, foreign keys) with a one-time migration from the legacy `data/api-keys.json`; `session.ts` persists in-memory `Map`s of hubs/accounts to `data/hubs.json` via atomic temp-file + rename. Runtime state lives under `data/` resolved relative to the source file via `fileURLToPath(import.meta.url)` rather than CWD.
