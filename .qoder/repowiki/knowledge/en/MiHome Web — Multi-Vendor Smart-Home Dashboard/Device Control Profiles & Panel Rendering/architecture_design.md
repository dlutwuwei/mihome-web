Three-layer model defined in `types.ts`: `VendorField` (vendor adapter output), `DeviceProfile` + `FieldRule` (configurable converter profiles), and `ResolvedField` / `DeviceDetail` (final UI payload). Internal layering:
- `profiles.ts` — registry of built-in and on-disk JSON profiles under `data/profiles`, with tiered matching (`did > model > specType > vendor`) and glob-based pattern matching; exposes `resolveProfile`, `resolveRule`, `listProfiles`, `saveProfile`, `setProfileDir`.
- `codecs.ts` — registry of bidirectional `Codec` implementations (`identity`, `bool`, `shape*`, `number`, `scale`, `offset`, `map`, `duration`, `auto`, etc.) keyed by name, pluggable via `registerCodec`.
- `panel.ts` — single composition entry `buildPanel` that merges adapter fields with profile rules, infers `ControlKind` (`switch|segmented|select|slider|number|text`), picks a codec, decodes values, groups into services/properties/actions, and provides `encodeFieldValue` for write-back.
- `profiles/` — vendor-specific built-in profile arrays (`xiaomi.ts`, `midea.ts`, `pantum.ts`, plus `demoProfiles`) registered at bootstrap via `bootstrapProfiles()` in `index.ts`.
Dependency direction is one-way: `panel.ts` → `profiles.ts` + `codecs.ts`; `profiles/*.ts` → nothing in this module. The runtime profile directory defaults to `data/profiles` (overridable via `MIHOME_PROFILE_DIR` or `setProfileDir`) and is reloaded on each read using an mtime stamp cache.
