Two entry points compose the HTTP server: `src/index.ts` boots providers via `bootstrapProviders()` then calls `createApp()` from `src/app.ts`, which mounts route modules under `/api/*` and serves static assets from `../public`. The `src/core/` directory holds framework-agnostic server primitives with a clear dependency direction — `status.ts` depends on `registry.ts` and `session.ts`, both of which depend on `errors.ts`; `apikey.ts` is self-contained. Stateful modules (`apikey.ts`, `session.ts`) persist their in-memory Maps to JSON files under `data/` (paths resolved relative to the module via `fileURLToPath(import.meta.url)`), using atomic temp-file + rename writes with `mode 0o600`. `registry.ts` exposes a singleton Map of `VendorProvider`s keyed by id, used by `status.ts` to resolve vendor-specific session probes. `errors.ts` defines `AppError` plus `isAuthFailure` / `toPublicError` helpers that downstream layers use to classify login-state vs transient failures.
